 **Handling Asynchronous Time-Series Data & Dynamic Slicing**

### 1. The Exact Issue (Tujhe problem kahan aayi thi?)

* **The Problem:** Jab tune FRED API se data pull karke ek single `master_table.csv` banaya, toh tune dekha ki recession indicator (`USREC`) ka data **1854** se available hai, lekin employment sectors (`PAYEMS`, `USINFO`, `MANEMP`) ka data sirf **1939** se start hota hai. Iski wajah se 1939 se pehle ke rows mein employment wale columns **blank (NaN)** dikh rahe the.


* **The Confusion:** Tu confuse ho gaya tha ki kya mujhe pre-1939 ka sara data delete kar dena chahiye ya is master table ko tod kar (normalize karke) do alag tables banani chahiyein taaki charts mein discrepancy na aaye.

---

### 2. The Concept We Used to Solve It (Humne kya concept use kiya?)

* **The Concept:** **Handling Asynchronous Time-Series Data & Dynamic Slicing (Selective Data Filtering)**.
* **Iska Matlab Kya Hai?**
* Real-world data analysis mein yeh ek **bohot common baat** hai ki alag-alag metrics (variables) ki history alag-alag time se record hona shuru hoti hai.
* Ek professional data analyst kabhi bhi purana historical data (jaise 1854 ki recessions) **delete nahi karta**, kyunki wo project ki strength hota hai.
* Aur na hi wo bina wajah tables ko todta hai (normalization databases ke liye hota hai, Jupyter Notebook EDA ke liye nahi).
* Iske bajaye, hum **single master table** rakhte hain aur Pandas mein **dynamic filtering / conditional slicing** (jaise `dropna(subset=[...])` ya date filtering) use karte hain—matlab jab jo chart banana ho, bas utna hi valid data slice karke use karte hain.
